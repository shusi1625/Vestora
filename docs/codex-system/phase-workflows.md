# Phase Workflow

Optional reference. Phase acceptance criteria live in docs/roadmap/phases/, not duplicated here.

1. Select the requested phase file by name; do not read the whole roadmap.
2. Check current source and git status for its affected area.
3. Implement a bounded slice and run risk-appropriate checks.
4. Compare evidence against the acceptance criteria.
5. Document or commit only if requested. Cloud rollout requires explicit approval.

For recovery/consistency work use [Phase 9.6](../roadmap/phases/phase-09-6-recovery-consistency.md).
For another phase, locate its file rather than assuming Phase 9.6 is current.
Planning, review and verification are responsibilities, not mandatory separate agents.
