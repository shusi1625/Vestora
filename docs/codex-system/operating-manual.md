# Operating Manual

Optional reference. Root AGENTS.md owns common safety and working-mode rules.

- Learning-led is default: purpose, small code/command, explanation, success criterion. User executes.
- Explicit implementation: announce scope, edit, verify, summarize. Do not require a planning subagent.
- Goal mode only on request. Define one bounded outcome, acceptance checks and approval boundaries; stop expanding scope once met.
- A phase needs its matching document, not all historical phases. Add architecture docs only for a concrete unresolved dependency.
- Main agent normally implements and verifies. Independent review is optional when risk warrants it.
- Finish with changed files, actual checks, remaining risk. Documentation/commit/deployment are separate obligations only when requested.
- At phase boundaries, prefer a fresh chat in C:/GitHub/Vestora with handoff.md and one next objective. Do not paste the entire chat.
- Obsidian is planning history, consulted only when repo evidence is insufficient. No automatic duplicate diary or Obsidian commit.
