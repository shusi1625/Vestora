## 여섯 흐름의 공통 예외

- 미연결/잘못된 네트워크: 개인 화면 게이트 및 Sepolia 전환 안내 구현; 브라우저 확인 필요.
- 잔액 부족: 생성/구매 입력·컨트롤러 검사; ETH 가스비는 지갑에서 확인하며 사전 가스 추정은 제공하지 않음.
- 사용자 거절: provider code 4001 및 cause 체인을 분류, 제출 전 거절을 별도 표시; 회귀 테스트 통과.
- 거래 실패: reverted receipt와 제출 후 미확인 결과 구분; 미확인은 중복 실행 방지.
- 반영 지연: receipt block과 projection block 구분, 갱신 실패를 거래 실패로 표시하지 않음.
- 새로고침: 저장된 공개 거래 정보를 복구하고 수동 결과 조회; 자동 서명/승인 후 자동 구매 없음.
- 기록 범위: 내역 API가 모든 거래를 제공하지 않아 부분 내역임을 표시한다.

## 다음 검증 순서

1. 사용자가 기존 오류 탭을 정상 로컬 URL로 열어 브라우저 접근 상태를 복구.
2. 공개 화면 및 샘플 상태: 360/768/1440, 키보드, 긴 데이터/오류를 한 번의 행렬로 검증.
3. 연결 지갑 UI는 서명 없이 검증 가능한 범위를 확인; 실제 서명은 사용자 실행 체크리스트로 구분.
4. 발견된 결함만 수정하고 해당 범위를 재검증. 모든 조건의 근거가 채워진 뒤 완료 판정.
