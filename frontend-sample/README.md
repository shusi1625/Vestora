# Vestora Integrated Frontend

Vite/React UI initially collected from Enter and then integrated with Vestora's Sepolia API and wallet adapters. This directory remains separate from the Next.js `../frontend` until the approved promotion is performed. No Vercel deployment has occurred at the 2026-10-23 documentation checkpoint.

## Current Behavior

- Live data is the default. `VITE_DATA_MODE=sample` explicitly enables isolated prototype data; a failed live read never falls back to sample values.
- Market, owned assets, sales, issued payments, payment creation and transaction history have dedicated workspace views.
- Live claim and exact-amount approval/fully funded payment creation are connected behind review and explicit wallet approval.
- Live buy/list/unlist/payment-cancel actions remain disabled. Prototype transaction success is not on-chain evidence.
- Holdings and issued-payment accounting are distinct. Cancellation retains vested unclaimed rights; future rights disappear and unvested funds return to the sender.
- Ownership and amounts are projected read values. Execution rechecks the chain; unknown wallet balances are not synthetic zeroes.
- The UI supports filter/sort, card/table views, 40-item market pagination, asset composition, payment names and dismissible terminal notices. Pending/unknown safety notices remain visible.

See [live data](docs/live-data.md), [claim execution](docs/claim-execution.md), [payment creation](docs/payment-creation.md), and [UI integration](docs/ui-integration.md). Earlier dated notes within those documents describe historical stages; the current execution boundaries above take precedence.

## Run Locally

```powershell
cd frontend-sample
npm ci
npm run dev -- --host 127.0.0.1 --port 4190
```

Open `http://127.0.0.1:4190/market`. Personal pages accept a connected wallet or an explicitly entered watch-only address; a watch-only address cannot sign.

`.env.example` contains public configuration examples. Vite's dev/preview `/vestora-api` proxy is not shipped in a static build. A production host must provide an appropriate server-side API route or an HTTPS API with the intended CORS policy. The plain-HTTP API IP is replaceable infrastructure, not a permanent public endpoint recommendation.

## Verify

```powershell
npm run check
npm run test:load-safety
npm run test:ui-performance
npm run qa:ui-typecheck
npm run build:prod
```

Normal application output is `dist/`. `qa-dist/`, `qa-ui-dist/` and `qa-ui-actual-dist/` are local test outputs and must not be deployed or committed. QA entrypoints replace wallet/RPC transports and are not production wallet implementations.

- [Manual QA tools](tests/manual-qa/README.md) exercise local fixture scenarios; they do not prove every actual-wallet case.
- [Load-safety harness](tests/performance/README.md) is closed by default and is not authorization to send production load.
- [UI measurement harness](tests/performance-ui/README.md) separates fixture/actual sources, API and UI-only intervals, commits and frame callbacks.
- The repository [performance checkpoint](../docs/report/performance-status-2026-10-23.md) records incomplete actual G2/G3 measurements and remaining work.

- [Collection](docs/collection.md) and [original verification](docs/verification.md): historical scope and screenshots, not evidence of the latest live behavior.

Pretendard uses the original jsDelivr CDN; this is not a fully offline bundle. Transaction recovery uses origin-scoped browser storage, so a new deployment domain requires an explicit recovery/safety plan. The unresolved B-account #3 hashless claim must not be retried or cleared merely because a new origin has no local record.
